# 本人确认交易与恢复的产品契约

## 实际入口与责任

主进程只创建一个 MacThsOrderService，使用规范的应用数据目录，持有 SQLite 意图库与受监督执行适配器。启动和状态读取不建库、不调用同花顺、不授权或重放订单。Windows 不打开此订单库，投研与本地账户账本保持独立。

可信 IPC 在 execute、recover 和 reviewIntent 调用前验证当前主窗口与主 frame。通知只触发重新读取；界面拒绝过期序号、退役会话和未同步的操作回报。退出先撤销授权和准入，再等待执行者真实退出，最后关闭订单库；研究任务的等待超时不能豁免交易执行者保护。

## 授权不等于可下单

- canAuthorizeLive 表示可以申请新的会话授权，不是订单准备或提交权限。需要已初始化、无存储/恢复阻断、执行空闲、没有未核对意图、活动操作或确认票，且会话尚未启用。
- 恢复后 canPrepare 保持 false，直到新的原生账户授权成功。界面不能反过来把 canPrepare 当作申请授权的前提，否则恢复流程无法走完。
- 新字段只为旧投影兼容而可选。缺失时保留原 canPrepare 门禁；明确 false 不得被兼容分支覆盖，错误类型拒绝整个投影。
- 启用仍经过已有应用确认票、本人原生确认、辅助功能检查、新的账户与模式观察，以及持久库会话门禁。勾选、人审核对、重启或通信失败都不能代替授权。
- 准备和提交绑定固定请求编号、不可变快照、账户、价格、数量、金额上限、修订版本、调用者和双时钟有效期。真实副作用前持久消耗执行许可，同一意图不能再次领取执行。

## 结果未知与逐条核对

可能已提交但没有可信回报时保持 UNKNOWN。进程死亡、无回报或失去 IPC 回执均不能触发自动补发；主进程死亡也不是执行者退出证据。

恢复只使用符合要求的封存来源，保留原件和永久编号，旧意图永远不可执行。恢复计划绑定编号、清单摘要和预期版本，并须本人原生确认。未受监督残件不能通过清空或移走来伪造新域。

人审逐条绑定意图、快照摘要、修订、恢复编号及本次核对编号。仍不确定或检查范围不足不能释放门禁。解除一条不解除其他意图、不把 UNKNOWN 改为机器观察成交、不删除执行禁令、不授权会话。明确追加订单也必须使用新意图和新的逐笔确认。

同一页面展示恢复、逐条核对和重新授权下一步。恢复与人审回报未知时不重复写入，先读权威状态。反馈继续从白名单生成，不含账户、订单参数、编号、摘要、路径、凭证或确认票。

## 1.20 验收边界

新增真实 SQLite 服务链检查：受监督的合成旧来源退出、恢复、人审、取消原生授权、再次本人确认后的合成账户观察及重启。适配器只运行测试 Node 子进程，不运行真实委托。界面门禁覆盖未同步、回报未知、待核对、非支持系统和退出未证明状态。

真实客户端与账户兼容、实际安装包中的完整恢复交互和券商回报仍需单独证据。定义本契约只完成架构任务 7.1，不将其他交易任务或产品总目标标记完成。
