# 应用更新与安装位置

RT-ResearchFlow 1.0 的配置中心新增“应用更新”。这是统一产品的发布入口，不是另一套应用。

## 使用方式

1. 打开配置中心，选择“应用更新”，查看当前产品版本、构建版本和程序目录。
2. 点击“检查更新”。默认查看正式发布；当前为测试版本时默认包含测试发布，也可自行切换。
3. 如果当前系统、芯片对应的安装包已经上传完成，点击“下载并校验安装包”。
4. 下载完成后点击“打开已校验安装包的位置”。
5. 结束正在进行的交易操作，先备份数据，再自行运行 Windows 安装包或替换 Mac 应用。

开发环境只查看发布信息，不下载安装包。检查发现发布版本低于当前应用时不会提供降级。

## 位置与版本

- Windows 默认下载位置在当前程序安装盘的同级目录 `RT-ResearchFlow-Downloads`，不默认跳到 C 盘。可以通过“选择下载位置”改到其他盘符，选择会保存在应用本地配置中。
- macOS 默认下载到系统下载目录下的 `RT-ResearchFlow-Downloads`，同样可以更换位置。
- 下载目录必须与程序目录分开；本模块不会删除旧应用、覆盖数据库、改变安装目录或自动退出程序。
- 产品显示 1.0、1.1、1.2；内部版本和安装包使用 1.0.0、1.1.0、1.2.0。按数值比较，1.10 高于 1.9，不按字符串或发布时间误判。

## 下载验证

- 更新仓库固定为 `hzqedison/RT-ResearchFlow`，不接受页面传来的任意下载 URL。
- 根据当前系统与进程架构选择 EXE 或 DMG；不下载源码 ZIP、其他芯片安装包或缺失的资源。
- 校验 GitHub 资产提供的 SHA-256；缺少资产摘要时从同一版本的 `SHA256SUMS.txt` 获取摘要。没有有效摘要时不提供应用内下载。
- 下载到随机临时文件，流式核对文件大小和摘要，通过后才保存为安装包。同名已有文件先校验，正确则复用，错误则拒绝覆盖。
- 支持取消和超时处理；失败时清理本次临时文件，不自动运行任何可执行文件。
- 仅访问允许的 HTTPS GitHub 下载域名，重定向次数、更新响应大小和安装包大小都有限制。请求不携带账户、大模型 Key 或网站 Cookie。
- SHA-256 是完整性验证，不是开发者签名、公证或交易接口认证。

## 尚未完成的升级能力

本版仍然下载完整安装包。自动覆盖安装、差分下载、后台自动更新、安装失败回滚还没有接入，不能把本入口宣传成已经完成的增量更新系统。

后续真正的增量更新需要同步完善发布元数据、差分资产、安装路径与数据保留、退出时交易状态检查、失败恢复以及平台签名方案；完成对应验证后才能启用。
