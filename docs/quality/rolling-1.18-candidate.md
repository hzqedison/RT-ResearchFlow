# 1.18 滚动验证候选

状态：主路径本地隔离验收通过，异常恢复入口存在已复现缺陷；候选未发布、未开始三端原生构建。1.17 正式包不变。

产品路径：策略评估 → 样本外验证 → 固定协议 → 逐份训练报告 → 独立提交训练选择 → 隔离后测试 → 本地保存与恢复。使用 1.17 共享现金模型；实验室按具体已完成批次，短线按具体已保存来源选择。

训练净收益降序、回撤升序和预设候选顺序是唯一选择规则。所有测试窗口保留，测试亏损不被过滤；空样本不记零收益。最多 12 个测试窗口、8 个持有期候选，日历须覆盖全部自然日；隔离开市日数不能小于最大候选持有期。

每窗重新使用手动研究预算，不使用当前账户余额，不把窗口均值说成连续组合净值、复利或年化收益。价格口径、日线撮合、信号时点、公司行动仍沿用 1.17 限制；市场事实摘要逐报告捕获，并非整段市场数据一次性冻结。不能据此声称已消除所有前视偏差。

待验收：协议幂等、日期及窗口无重叠、训练选择不依赖测试、质量阈值、测试亏损与缺样本、先提交选择再测试、抢先测试报告拒绝、日历变化、报告与步骤原子性、恢复和可信 IPC、实际程序页面与重启、三端原生包。研报全文及研究复盘仍未补齐，完整 5.4 保持未完成。

- 20 项协议、窗口、训练选择及实际 SQLite 测试，3 项可信 IPC 测试，2 项服务端渲染说明/入口测试通过；另有 1.17 资金引擎与服务的 34 项回归，共 59 项通过。Node/Web 类型检查均退出 0。
- 初次事务回滚断言错误：SQLite 连新建的报告表也回滚，不能直接查询尚不存在的表。测试改为预先建立空报告表，再证明失败写入回滚。未放宽事务行为。

- 生产构建与 Windows x64 打包目录生成通过，没有重建共享原生模块。
- 实际打包程序的账户账本、共享资金及滚动协议、初始化、启动/设置/退出共 4 项通过（56.9 秒）。滚动协议先保存为 0/2 报告，再分别完成训练、落库选择和测试，真实测试均值 0.00%；退出重启后按同一研究编号读取完成状态。全部使用隔离用户目录。

## 已复现但未修复的发布阻断

`tests/e2e/packaged-rolling-recovery.spec.ts` 在实际候选中使用隔离数据库触发器模拟协议保存失败，随后移除触发器并通过真实 IPC 查询该编号。协议确实未保存，但页面保留 `uncertain`，日期输入及新建按钮继续禁用；`toBeEnabled` 断言失败。此测试已接入 Windows 与两种 Mac 的原生发布门槛，未通过不能产生滚动验证证明。
