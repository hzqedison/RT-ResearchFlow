# 1.18 退出与手动任务边界审查

日期：2026-10-12。当前为开发候选，正式 1.17 未改动；完整架构任务 4.4 未完成。

## 当前源码能证明什么

- 主程序退出时关闭心跳、调度器、清理定时器及扫描入口，并令可信窗口获取器不再返回新调用者。
- `SchedulerTaskHost` 可以失效旧定时任务代次，跟踪已经进入主机的异步工作，包括父任务结束时进入的子任务。停止定时器不取消已有 Promise，等待超时仍保留任务记录。
- 清理服务执行同步数据库操作，停止后释放小时定时器；不能将其行为推广为所有异步同步任务的退出证明。
- `stopApplication` 对研究任务采用 8 秒宽限；调度器和扫描的 5 秒等待结果不等于全应用归零。真实订单执行器的 `shutdown` 另行等待，研究任务超时不是交易关闭证明。
- 数据库模块提供 `closeDb`，但当前应用退出流程没有主动调用它；未证实“退出提前关闭数据库后仍写入”这一猜测，不据此盲目修改数据库关闭顺序。

## 仍需实现或验证

- 调度器明确不覆盖独立手动任务、其他服务分离工作、所有 IPC 和应用外部任务；全局任务准入及资源归属未证明。
- 审查时免费历史同步仅暴露运行状态，没有调用方取消信号；本轮已按下方证据补齐公共历史及证券列表路径。Tushare 历史同步选项仍没有取消信号，不能推广为所有手动任务已取消。
- 下一步应分别定义手动同步的停止准入、取消当前网络请求、保留已提交检查点、停止后续批次及完整空闲证明，然后接入应用退出。需要覆盖请求排队、网络等待、返回后写入、冷却/批次等待、重启续传，以及 Windows/Mac 实际程序；不以简单超时或强杀作为验收通过。
- C 盘共享 Python、本机生产数据库及券商账户未被操作；没有再次尝试被策略拒绝的覆盖安装。

## 验收质量修正

原盘后契约测试使用字符串截取 `export async function runConceptMembersSyncForSource`，当前函数签名不含 async，可能得到空片段后让否定断言假阳性。现改为已存在的 TypeScript 语法树定位函数体；协调器和市场任务也使用相同定位，不再依赖下一个导出函数签名。新增缺失函数必须抛错的检查，以及停止定时器后手动工作仍被跟踪的真实 Promise 检查。

初始四个文件 56 项回归通过；强化后四文件 58 项全部通过（调度服务 36、盘后语法树契约 9、任务主机 9、清理器 4），耗时 2.79 秒。四文件回归已加入两种 Mac 与 Windows 原生构建门槛；本轮未触发远程构建，1.18 的异常恢复缺陷仍为发布阻断。测试通过不代表手动任务取消已经实现。

## 公共数据取消实现与本机证据

本轮新增 `PublicMarketWorkOwner`，用于公共历史批次、逐股历史请求、公共证券列表批次及直接列表请求。退出关闭这些入口的准入，取消它们的信号，并在已有研究退出等待中加入真实空闲等待。没有改变数据库关闭方式、交易确认或订单关闭证明。

请求队列取消时仍保持前序所有权，不让后续请求越过仍在执行的请求。默认冷却等待释放定时器；正在执行的请求不靠 Promise.race 假装完成。每次响应解析后、写入前核对取消。取消不增加供应方故障计数，不走腾讯兜底，不标作股票失败；成功检查点及累计写入量保留，中断股票回到 pending，批次为 partial。

- 新增三项缺口测试首次均失败，证实原实现忽略取消、继续下一个股票及不能取消队列等待。
- 28 项公共数据定向测试通过：取消 6、工作归属 7、原历史服务 6、请求队列 6、原证券列表 3；Node/Web 类型检查退出 0。
- 首轮漏将直接证券列表读取归属到退出所有者，扩展测试复现 pendingTasks 为 0；接入同一所有者后通过。另一失败是测试假定了错误的供应方状态表名，改为使用真实仓储 API，不放宽失败计数断言。
- 生产构建及 Windows x64 打包目录生成成功，未重建共享原生依赖。原有实际程序四项检查通过；新退出用例首次在数据目录保护处拒绝执行夹具，校正隔离边界后单独通过（3.9 秒）。
- 实际用例经已有 `diagnostics.runCheck('syncHistoricalDaily')` 启动手动任务，人工控制网络响应保持待返回，再正常退出。退出前读取真实 SQLite：批次 partial、处理/写入计数 0、中断股票 pending 且无错误、无晚到价格；请求确实收到一次取消，进程退出 0，而不是等 15 秒网络超时。
- Windows 按既定产品规则使用 `release/win-unpacked/data` 沙箱，CLI profile 仅提供浏览器参数；Mac 使用独立 CLI profile。构建沙箱不是用户的 `D:/Program Files/RT-ResearchFlow`，本轮没有操作正式安装数据库、共享 C 盘 Python或券商。

两种 Mac 与 Windows 已加入相同单元和实际退出检查，原生证明及发布器对 1.18 要求 `localPublicWorkShutdownVerified`。尚未触发本轮远程构建，不能声称 Mac 已通过。Tushare、其他后台服务、所有调用者的后续工作、外部进程与完整异常退出仍未覆盖，4.4 保持未完成；1.18 恢复入口缺陷未解决，仍不发布。

最终综合回归：15 文件、145 项通过（9.27 秒），包括公共数据 28、生命周期 58、资金及滚动研究 59；Node/Web 类型检查均退出 0。1.18 的已知异常恢复回归不在这 145 项通过之列，其失败证据及发布阻断保留在 `rolling-1.18-candidate.md`，没有将它隐藏为已通过或跳过后发布。
