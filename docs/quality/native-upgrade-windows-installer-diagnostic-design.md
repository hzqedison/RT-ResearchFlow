# Windows 1.0 原始安装器受控诊断方案

日期：2026-10-08。设计与最终裁定：Astra。状态：**DESIGN_ONLY / NOT_EXECUTED**。

本设计仅处理 F2；不重复 Sol 正在实施的 F1/F3 修复，不修改执行器、工作流或产品。本轮不触发 CI，不运行本机安装器，不重新下载安装包或证据产物。依据是上一轮本人已读取并记录的指定 run 日志和脱敏 JSON，而非实现代理的摘要。

## 1. 已知事实与未知原因

既有证据：[run 37726873605 attempt 1](https://github.com/hzqedison/RT-ResearchFlow/actions/runs/37726873605)，Windows job [113147009285](https://github.com/hzqedison/RT-ResearchFlow/actions/runs/37726873605/job/113147009285)。原始 artifact 为 [11528012760](https://github.com/hzqedison/RT-ResearchFlow/actions/runs/37726873605/artifacts/11528012760)，2480 字节，独立回读 SHA-256 为 `12595b4749115919d12c5cf422f9b11c95c96d56d0ccf7a5a17fa7cf56004f87`。

| 能确定的事实 | 不能由此推出的结论 |
| --- | --- |
| 固定旧 1.0 EXE 的安装进程退出 `-1073741819 / 0xC0000005`，耗时 3254 ms | 不能断言 1.1 升级逻辑或数据库迁移出错 |
| 关联采集的应用错误记录包含 `System.dll`、版本 `0.0.0.0`、异常 `c0000005`、偏移 `00001581` | 文件名不能证明它是 Windows 系统 DLL；没有完整模块归属、哈希和调用栈，不能定位具体函数或组件 |
| 执行环境为 Windows Server 2025 / 10.0.26100，镜像 `windows-2025-vs2026`，版本 `20260925.250.1` | 未证明是系统版本、特定补丁、进程缓解策略、权限或安全软件导致 |
| 调用路径是静默 `/S`、owned 目录 `/D=`；安装前已进行应用专属网络规则和 WFP 审计 setup | 未证明参数、环境传递或 runner 条件完全无关；也不能把先后发生当作因果 |
| artifact 中 phases 为空，唯一通过断言为隔离前公共探测可达；没有 1.1 安装事件 | 不能声称跨版升级、正常退出、数据保留或四阶段隔离已验证 |
| 独立清理步骤成功，collect 正确失败 | 清理成功不等于安装成功或应用正常退出 |

尚缺：实际异常进程与父子关系、事件 PID/启动时间严格关联、故障模块的路径类别/字节身份、安装前权限和进程缓解策略、崩溃时所处安装阶段。上一轮只发布了收窄后的事件字段，不能事后从不存在的字段推断根因。

先前其他版本也曾出现同一异常码，只能作为线索，不能合并为同一故障。本方案不引用它作为本次根因证明。

## 2. 永不改变的输入与隔离契约

| 字段 | 固定值 |
| --- | --- |
| 基线版本/tag | `1.0.0` / `v1.0.0` |
| 正式 source | `41f8429149f646c7dec7f1610082702e7d9cce48` |
| 文件名 | `RT-ResearchFlow-Setup-1.0.0-x64.exe` |
| 字节数 | `166547210` |
| SHA-256 | `f5ea701458902dbcdeea08b3aabbcfca23b2c2c6a16ed8b88de1b31811033a4b` |

- 仅 GitHub-hosted 一次性 Windows runner，单 job、单 owned case、无重试策略。先完成 F1/F3 的独立预检、冻结和运行时字节核对，再允许安装调用。
- 后续执行如获 Astra 放行，只通过已有固定下载器在 runner 内取得并校验上述原始 EXE；安装前、安装退出后各校验字节。不得为本轮设计在本机下载或执行它，也不得另找镜像包、改 tag、重签名、重打包或解包安装。
- 每次实验均是全新 runner 和空安装目标，无既存同身份注册项或相关进程；不得在同一个已部分失败的安装现场再次执行安装器。
- 保持既有 `/S`、`/D=<CASE>/install`、隐藏启动、安装等待上限、调用方式、网络规则、WFP 审计和凭证剔除环境契约。不得顺带改变启动参数、用户提权方式、兼容模式、TEMP/TMP 或安全设置。
- 不接触真实账户、生产数据、真实 API Key。诊断不手动启动已安装应用，不保存测试密钥，不调用券商或交易接口。安装器若自动启动产品，记录并按 owned 进程规则停止，不把该行为算作 A 阶段启动。
- 不关闭 Defender、ASLR、DEP、CET 或其他进程安全策略；不删除隔离规则。安全策略只读观察。需要改变这些条件时，本方案不予授权，必须先由 Astra 单独评估。
- runner 的 SID、机器标识和随机 case 路径自然会变；使用散列身份和规范化路径类别比较，不强求跨机器 SID 相等。同一升级案例内的身份/数据目录一致性要求不因此放宽。
- 本轮不改已发布 1.1、正式 release 工作流或公开 assets。未来诊断输出只归入专用 acceptance 分支和诊断证据，不混成正式升级通过记录。

## 3. 最小观察字段

采用白名单结构化证据；原始事件只在 runner 内存中解析，不上传完整事件 XML、命令行、环境、注册表或用户路径。

| 观察阶段 | 必需字段 | 用途与边界 |
| --- | --- | --- |
| 输入与身份 | harness commit/组合摘要、run/attempt/job/case、EXE 前后 SHA/size、目标 tag/source | 排除换包、混 run、未审代码；身份不是安装成功证据 |
| runner | OS edition/build、runner image/version、CPU 与安装器实际进程架构、Node/PowerShell 版本 | 区分镜像漂移；不凭 `x64.exe` 文件名推断内部安装器进程架构 |
| 安装前 | 空目录/注册项/进程检查、有效用户 SID 哈希、是否提升及完整性级别、可观察到的有效缓解策略 | 排除残留与权限条件差异；不可因观察困难改策略 |
| 路径与调用 | 参数形状 `/S /D=<CASE>/install`、cwd/TEMP/TMP 的路径类别/长度/是否含空格或非 ASCII、是否本地卷/链接、必要的可写检查布尔值 | 不上传绝对路径；不通过缩短路径或改 TEMP 偷换 D0 条件 |
| 进程 | 安装器 PID、启动/退出 UTC、父子关系、子进程映像 basename/受控路径类别、关联退出码 | 区分安装引导进程、安装器子进程和产品自动启动；父进程退出不替代子进程状态 |
| 错误事件 | Application Error/WER 的 provider、event ID、record ID、时间、关联 PID、异常码、模块 basename/version/offset | 时间范围加 PID/进程身份关联；仅同名进程事件不能作为确定归属 |
| 模块归属 | 故障模块属于 Windows 目录、NSIS 临时目录、安装目录或其他；若原文件仍存在则只读取 SHA/size/签名状态 | 区分同名 DLL。不存在就明确 unavailable，不再执行安装器只为补取，也不手工解包提取替代 |
| 结果与清理 | 最后可证实阶段、原始退出码、主失败、独立清理结果、owned 子进程是否结束 | 不以清理成功覆盖原始失败；不从已落地文件数量推断安装完成 |

记录所有阶段的 UTC 时间。退出后读取本次时间窗口内的已有应用错误/WER 事件，可有界等待最多 60 秒供事件落盘；没有事件就明确 missing。这个等待不是安装重试，也不得无限轮询。

不默认启用崩溃 dump、调试器、ProcMon、全量 ETW 或 WER 注册表改写。它们可能改变运行条件或扩大敏感数据范围；只有只读证据仍不足、且 Astra 明确设计下一步时才讨论。模块观察失败不能成为放宽脱敏或重新运行至取得理想日志的理由。

## 4. 最小实验计划：历史 R0 + 至多两次新增执行

### R0：保留现有失败，不再执行

R0 就是 run 37726873605 attempt 1。既有原始退出码、镜像版本和 artifact 摘要为历史比较锚点。其失败不删除、不改写，也不追加 GitHub 原地自动 rerun。

### D0：一次同条件诊断复现，唯一新增项是只读观察

目标：补齐安装进程/事件/模块归属，不尝试修复安装器。使用修复后的验收工具与固定原始 EXE，保留既有行为参数，记录第 3 节字段。安装器只启动一次。

开始前对照 R0 镜像信息。`windows-latest` 不是固定镜像；仅改成某个 OS 标签也不能锁住 hosted image 的内部版本。若无法获得原始 image/version，应标记为“新环境诊断观察”，**不得称严格同条件复现**，也不得悄悄将它作为后续因果对照基线。如果缺少公平对照所需条件，由 Astra 收敛范围或保持 BLOCKED，不增加尝试次数补偿。

D0 的只读观察不得改变安装参数、挂调试器、延缓/拦截 DLL 清理或修改系统策略。观测引入的额外工作需要声明；不能宣称绝对无观察影响。

- D0 再现相同异常：依据严格关联事件和模块身份决定是否满足 D1 条件；先报告，再裁定，不立即重复 D0。
- D0 成功：只证明固定旧包在这次环境能完成首次安装。R0 原因仍未解释，立即结束本次诊断，不宣称修复或升级通过，不继续试到“连续成功”。
- D0 出现不同异常、环境/隔离/字节不符、事件归属不清或诊断自身失败：停止，交回具体证据。不得以同一 run rerun 消除异常。

### D1：条件性的一次 runner 镜像对照

只在 D0 已有充分错误归属、仍复现原安装异常、且没有明确参数/权限/文件完整性/验收工具错误时，才由 Astra 决定开展。预注册假设为：**该固定旧安装器的失败与 hosted runner 镜像环境有关**。

唯一主动改变的实验因子是 runner OS/image 组合。例如在确认为 GitHub 提供且满足隔离要求时，采用 `windows-2022` 与 D0 的 Windows 2025 环境比较；本设计不假定标签当前必然可用。记录两边准确 image/version，控制相同 harness 字节、原始 EXE、安装参数、可固定的工具版本、权限方式、路径形状和安全隔离流程。无法保持的差异必须列出。

这是“镜像环境”这个组合因子的对照，**不是单独更换某个系统补丁、CPU 缓解策略或 DLL 的实验**。若多个主动条件需要一起改变，取消 D1，不把多变量实验包装为单变量。

D1 同样全新 runner、一次安装，无回退重试。不得在 D1 同时修改静默/可见模式、提权、临时目录、防火墙或兼容性开关。D1 无论成功、失败、超时或证据缺失，本轮安装执行预算即结束。

## 5. 预先定义的判定与停止规则

| 观察结果 | 可支持的结论 | 不可支持的结论/下一步 |
| --- | --- | --- |
| D0 同条件再现，模块归属与字节身份充分 | 同条件重复性增强，定位范围缩小 | 尚不能仅凭模块名/偏移认定源码缺陷 |
| D0 直接成功 | 旧包在该次环境首次安装可成功；原异常可能非稳定复现 | 不证明根因已修复，不删除 R0，不自动 rerun 求稳定 |
| D0 失败、D1 成功，其他受控条件满足 | 支持镜像环境相关性 | 不能确定某项系统策略为根因；不能证明升级数据保留 |
| D0/D1 同样失败且同模块字节/偏移 | 支持故障跨两环境存在 | 不自动把错误归为 1.1 或直接批准改正式安装包 |
| D1 失败类型不同或存在未控制差异 | 对照不充分/结论不确定 | 不扩大矩阵或换第三种环境继续碰运气 |
| 哈希、身份、隔离、权限契约或诊断完整性不满足 | BLOCKED_INPUT / BLOCKED_ENVIRONMENT / 工具阻断，按实际证据分类 | 不开始或不继续安装，不改门槛为通过 |

**硬停止：** 固定 EXE 不符；碰到非 owned 状态；安装器或子进程越界；关键隔离条件无法维持；取证可能外发敏感数据；需要改变未批准安全策略；原始失败无法安全保存；D0/D1 的预算用尽。超时保留真实超时和 owned 清理结果，不用另一次成功覆盖。

本方案只预设 R0 之后最多 D0、D1 两次新增安装进程启动，且 D1 非自动必跑。既有失败 run 不能被按钮 rerun 增加隐含样本；若后续确有新的因果假设，须 Astra 另写有界实验，不冒充本方案延续。

## 6. 安装诊断与升级验收的边界

即便某次安装退出 0，也必须结合同身份注册项、安装路径、版本、owned 进程与清理状态才能称该次首次安装成功；单凭文件存在、退出 0 或截图均不足。**首次安装成功永远不是升级通过。**

跨版升级放行仍需后续由 Astra 独立控制的正式 A/B/C/D 证据：原始 1.0 安装并建立合成业务数据，正常退出后独立进程重启读取；同身份同目录由原始 1.1 EXE 覆盖升级；再经过两个新版独立进程、正常退出、数据库/配置/业务数据与隔离断言。不得手工复制已解包文件、换旧包、跳过旧版或以同版本重装替代。

本 Windows 诊断不能支持 Mac Keychain 的任何通过结论。即使 D1 在另一镜像安装成功，也只解决该镜像上的“是否可建立旧版基线”前置条件，不代表真实用户设备全部兼容。

## 7. 交接与独立性

本轮仅新增此设计报告。待 Sol 的 F1/F3 清单交付后，Astra 先独立复验其实现；F2 观察字段的后续实现也由 Sol 承担，限定在验收工具范围。Astra 审核冻结字节、预注册本次唯一变量和停止条件之后，主任务才可推进专用诊断执行。

每次实际执行分别保存 run/attempt、固定输入、环境差异、安装事件、缺失字段与结论，不合并为一个“绿灯”。最终测试和验收仍由 Astra 独立完成；开发自测、工作流绿色和本设计文档均不能代签。
