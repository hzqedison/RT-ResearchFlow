# 1.18 Tushare 历史任务取消候选

状态：定向隔离测试、类型检查、生产构建及 Windows 实际程序用例通过；两种 Mac 尚未原生验收。1.18 仍因滚动恢复入口缺陷而不发布，1.17 正式附件不改。

## 实现边界

历史任务复用已验证的纯工作归属实现，但使用独立于公共数据的所有者。退出关闭准入、取消请求与日期等待并等待真实结束；不按 Promise.race 把忽略取消的工作说成完成。日历、daily 和 daily_basic 传递同一历史任务信号；请求复用既有受限 Tushare 传输，保留正常权限和超时分类。

每次返回及提交前检查取消。中断日期不计成功或失败，已提交日期不删除；尚未提交的 OHLCV 即使已经收到，也不会在补充阶段取消后偷偷落库。停止进度可发送到仍存在的窗口，关闭窗口不再强行发送。显式本地取消不产生伪内部错误反馈，也不转换为超时/权限失败。

日历加入者可以取消自己的等待而不取消无关的既有所有者；被取消的自有请求不会写入或走官方兜底。无信号的现有调用保留原行为，包括正常的日历兜底和并发结果身份。独立日历任务、其他 Tushare 接口及所有应用后台工作仍不在完整关闭证明内。

## 实际证据与失败记录（2026-10-12）

- 首轮 5 项缺口测试均失败：忽略取消、继续下个日期，以及本地 AbortError 被错当成 Tushare 请求超时。
- 接入后 84 项定向测试通过，包括新增历史取消 6、传输取消 5、日历取消 3、诊断取消 2；既有历史服务 9、日历服务 4、权限分类 2、受限传输 53。Node/Web 类型检查均退出 0。
- 旧历史测试两处失败仅因调用增加信号参数，现断言真实 AbortSignal 与日历使用同一对象，没有删除内容或写入检查。
- 受限传输回归含真实本地 HTTP 流中断，不连接 Tushare 上游。取消重试等待、晚到响应、换手率补充和共享日历均保留负向检查。
- 实际生产构建及 Windows x64 打包目录成功，未重建共享原生依赖。
- 第一次实际 Tushare 退出用例发现中断日期多一行。只读查询确认其来源为新浪：Windows 共享构建沙箱在启动时续跑公共任务，并非目标 Tushare 写入。没有把零新增断言改成忽略该行。
- 改为独立 Windows 可执行文件布局：只复用静态文件字节及资源目录，不链接或复制原 data，数据仍保存在新可执行文件旁，符合产品规则。Mac 继续使用独立 CLI profile。该变化仅在测试辅助代码，不改变产品安装或数据路径。
- 独立实际用例通过（4.8 秒）：正常诊断入口读取本地加密的明确合成凭证，受控请求保持待返回，再触发正常退出；请求收到一次取消，进程退出 0，中断日期仍零行，处理/失败/成功日期计数均 0。原沙箱配置在退出前恢复；没有真实 Key 认证或订单提交。
- 公共退出用例在本轮新程序也通过；初次组合运行的失败保留，上述通过不冒充首次全绿。

两种 Mac 与 Windows 已加入同样的单元及实际程序门槛，证明字段为 `localSyntheticTushareWorkShutdownVerified`。尚未触发远程构建，不声称 Mac 原生通过。用户暂无真实 Key；绑定入口保持可见，合成凭证的本地可读性不是线上权限证明。

最终综合回归：24 文件、249 项全部通过（14.36 秒），包括本轮 84、既有公共数据/生命周期/研究 145 和凭证验证 20；Node/Web 类型检查均退出 0。已知滚动恢复失败用例仍独立保留，不在上述通过数内，发布阻断未取消。
