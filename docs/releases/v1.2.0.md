# RT-ResearchFlow 1.2

内部版本：`1.2.0`。Windows、Mac Apple 芯片和 Mac Intel 使用同一产品版本。可下载版本以发布页已公开的安装包为准；源码版本号不代表安装包已经发布。

## 本次改善

- **看得懂缺什么数据。** 区分真正缺失、按需缓存、未选择的题材源和尚未产生的派生结果；未参与检查的项目不冒充正常，竞价缺失仍如实显示。
- **按需补齐，不重建数据库。** 独立补齐竞价与精确前一交易日涨跌停事实，显示目标日期、写入情况和失败原因，不顺带运行策略或生成信号。
- **竞价不被无关缺口整体卡住。** 先获取真实竞价事实，再按分池的实际依赖判断；补齐或修订事实后，正常进入即可重建对应本地快照。
- **旧数据不冒充新观察。** 回填旧字段保留原观察资格，混合观察明确标记为部分就绪。09:28 的有效观察可用于当时判断，不因时钟到 09:30 就自动宣布数据完整。
- **失败不假报成功。** 区分无配置、权限拒绝、限流、超时、空结果、非法数字和异常分页；不保存未取完的分页子集，不以空值覆盖已有事实。
- **请求有边界。** 本轮有界采集共享单调时间预算、真实取消和分页限制；重复请求冷却不随快照淘汰或系统时钟调整失效。
- **题材按当前选择工作。** 初始化和同步按当前题材源判断，部分同步失败保留旧成员，不以成功子集全量替换。

## 更新后怎么用

1. 打开“配置中心 → 诊断”，先看当前来源及逐项说明。未选用的题材源、未请求的分钟缓存不需要为了消除提示全部填满。
2. 对竞价及前日涨跌停缺口，使用对应的单日补齐入口，核对返回日期与结果。默认初始化不等于所有扩展数据已经齐备。
3. 回到早盘竞价页，查看观察时间、缺少的输入和分池状态。没有输入不等于没有机会，样本不足也不等于收益为零。
4. 如仍失败，在诊断页生成脱敏反馈并手动导出。不要清空数据、发送 API Key 或发送券商凭据。

## 使用与验收边界

- 不提供共享 Key、不绕过来源权限，也不承诺免费完整竞价。接口实际返回合法数据才能补齐；Token 已保存不等于所有接口已授权。
- 部分记录不证明全市场覆盖；未知交易日历不按工作日猜测。截止后的实际采集也不自动证明完整覆盖。
- 本次不新增启动或休眠唤醒后的全量自动补偿，不保证快速初始化会生成策略评估样本。
- 本轮发布候选沿用 1.1 的交易执行功能，不包含尚未接入产品的交易存储实验代码，不宣称已通过真实券商或实盘验收。
- 保持产品身份、安装数据位置和 GitHub 更新来源不变，不要求清库重装。真实旧数据跨版本升级、目标 Mac 实际采集及所有设备兼容性仍须分别验证。
- 源码隔离验收见[数据就绪验收记录](../quality/astra-data-readiness-1.2.md)。最终安装包测试范围、源码提交和校验值，以该版本的 `RELEASE-PROVENANCE.json`、`SHA256SUMS.txt` 和构建记录为准，不能沿用 1.1 的通过结论。
