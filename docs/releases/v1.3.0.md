# RT-ResearchFlow 1.3.0 发行说明

用户可见版本：**1.3**；内部版本：**1.3.0**。本说明描述该版本的变化；可下载安装包、校验值与实际测试范围，以发布页已公开的对应版本记录为准。

## 同一款 Windows / Mac 产品

行情、资讯、AI 研究、研报与选股、策略验证、本人确认的交易流程和本地研究记录继续属于同一个工作台。Windows 与 Mac 是平台区别，Mac Apple 芯片与 Intel 是架构区别，不拆分成独立的“交易版”产品。

本轮强化已有的本人确认交易流程。本机执行代码路径目前仅适用于 Mac 同花顺；Windows 可使用投研与开通引导，**不执行同花顺实盘**。策略信号不会直接生成真实订单，不提供全自动或无人值守交易。

## 本轮实际新增与修复

1. **持久化不可重复订单意图**：操作与持久记录关联，确认沿用原请求编号及记录绑定，不因再次点击生成第二笔相同操作。未知结果保留门禁，重启不自动重发。
2. **本人确认与逐单核对**：每笔买卖或撤单仍需应用内核对与主服务原生确认；同花顺自己的券商弹窗由本人处理。未决结果按持久意图逐条核对，人工陈述不是机器对账或成交证明，释放新单门禁也不解除原意图的禁止重试记录。
3. **显式初始化与可信封存旧域导入**：后端确认无旧交易残件的新域，由本人明确初始化。对已可信封存、尚无 SQLite 的旧来源，先申请准备导入，经原生确认后以原封存凭据重新校验并建库，再返回恢复计划；用户之后仍须单独确认应用该计划。准备导入不是应用恢复，不自动启用真实会话，也不把旧域伪装成新域。
4. **默认专属目录安全检查**：交易记录使用默认专属目录并检查安全边界。存储不可用、执行器真实退出未被证实或服务停止中，继续保留保护；终止请求、超时或空回报不等于未提交或已取消。
5. **目标撤单与歧义拒绝**：修复最终撤单仅选中目标委托的路径；回读不一致或协议解释有歧义时拒绝继续，不用全撤或盲目点击替代指定委托核对。

## 从已发布 1.2 升级的限制

**未被可信封存的 1.2 旧交易日志，目前不能自动安全迁入。** 可信导入入口不适用于旧 1.2 未受监督的交易日志；没有可信封存证明时，交易模块保持阻断，不将未知旧记录当成空白新域。

- 保留旧交易日志、目录与保护状态，不通过清空记录、挪动目录或重新初始化伪装修复。
- 这项限制影响交易模块，不等于投研数据损坏，也不要求删除行情缓存、研究项目或判断记录。
- 恢复或人审回报未知时，不重复发送，不以重启作为重发手段；以最新权威状态继续核对。

1.2 已发布，数据诊断、初始化、交易日与竞价事实透明相关修复已独立验收；这些属于已发布版本的改进，不作为 1.3 新增功能重复列出。入口、来源权限与相应边界见 [1.2 发行说明](v1.2.0.md)。

## 验收与发布状态

- core、native 与 UI 的源码与隔离限定独立验收已通过，结论仅覆盖相应检查，不是目标 Mac 设备或真实券商交易验收。
- core 最终轮 74/74 与 12 组组合正反例通过；首轮 6 个探针建模失败的证据保留，不将首轮失败改写为通过，也不把这些计数扩大解释为全产品验收。
- Mac 实际编译与安装包验收须以发布页对应 CI 构建记录为准；源码与隔离检查不能代替原生安装验收。
- 真实 THS、Mac 辅助功能（AX）、真实账户的受理、成交及撤单尚未验证；安装检查、代码实现和替身测试不能替代这些验证。
- 全产品原生 IPC 链路、未受监督旧来源迁移及安装包不在本次限定验收范围；旧来源迁移限制仍按上节执行。

可下载版本、安装包校验值与实际测试范围，以发布页已公开的对应版本记录为准。不重命名或覆盖旧安装包冒充 1.3 构建。
